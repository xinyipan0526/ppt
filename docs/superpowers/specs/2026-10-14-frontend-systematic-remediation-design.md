# 前端系统性整改设计

## 1. 目标与范围

本批次修复 `docs/analysis/前端设计系统性总结.md` 中列出的全部 P0、P1、P2 问题，把当前“后端能力存在但前端不可达”的工作台补成完整、可恢复、可理解的一期产品体验。

本批次保持现有 React Router、TanStack Query、feature 目录、HttpOnly 会话、CSRF、SSE 与后端 Workflow 状态机边界。前端只投影服务端事实，不复制状态机，不推算没有服务端依据的 ETA，也不绕过预算、版本或人工恢复守卫。

以下内容不进入本批次：画布框选、手工涂抹、元素级可编辑 PPTX、云端多租户、移动端重构和真实 Provider 付费测试。

## 2. 实施策略

采用渐进式能力补齐方案：保留现有 feature 组件和工作区未提交改动，在现有结构上增加强类型契约、共享 UI 基元和组件级样式。只在前端无法从现有响应可靠推导数据时，扩展最小的后端只读投影。

不引入新的全局状态库、完整 UI 框架、大型图标依赖或生成式 API 客户端。所有新增服务器状态仍由 TanStack Query 管理；对话框内部输入、选中项和确认状态保留为局部 React 状态。

## 3. P0：恢复与成本闭环

### 3.1 Operation 级未知结果恢复

运行轨迹把 `outcome_unknown`、`reconciling` 和 `cancel_requested` Attempt 显示为需要人工处理的远端不确定结果。只有 `outcome_unknown` Attempt 可以发起显式重试授权；其他状态展示仍在对账或取消中的说明，避免提前授权。

授权流程必须：

1. 显示 Provider、模型、操作类型、Attempt 编号及重复计费风险。
2. 要求用户确认已在 Provider 控制台核对结果。
3. 调用 `/operations/{operation_id}/authorize-retry`，同时传递当前 `expected_attempt_id` 和中文风险确认原因。
4. 成功后刷新 Run trace、Run snapshot 和项目成本。
5. 当不存在未解决的远端不确定 Attempt 后，开放 Run 级 `/authorize-local-retry`。

Run 级恢复不再把服务端英文 409 作为终点。界面在 Operation 尚未处理时直接提示先完成逐条授权，并把用户定位到对应轨迹项。

### 3.2 成本、预留与预算

项目工作台顶栏显示每种币种的：

- 已结算费用；
- 有效预留；
- 远端结果未知而冻结的费用；
- 配置了硬预算时的预算总额和可用余额。

不同币种分别呈现，不执行隐含汇率换算。无法确定预算时明确显示“未设置硬预算”，不显示虚假余额。

现有 `/projects/{project_id}/costs` 只有 Usage 实际金额。后端需要在不改变账本语义的前提下，把 BudgetAccount 和 Reservation 的聚合结果加入同一安全只读响应。前端不得根据 Operation 状态自行计算金额。

### 3.3 状态动作指引

`recovery_required` 显示“核对 Provider → 逐条授权未知操作 → 恢复本地任务”。`waiting_for_retry` 只在服务端提供可靠时间时显示下次重试时间，否则显示“系统将按已保存策略自动重试”。所有状态使用中文产品语言，同时保留诊断区域中的原始安全状态码。

若当前 Run snapshot、trace 或恢复元数据无法稳定提供 due time，则增加最小只读字段；前端不得从轮询间隔或事件时间猜测。

## 4. P1：后端能力前端可达

### 4.1 Deck 代际

工作台提供 Deck 版本选择器，按 generation 倒序显示状态、创建时间、来源代际和全局修改说明。查看旧版本时清楚标记“历史版本”，导出、页面检查和历史查看使用当前选中的代际。

恢复旧版本使用统一确认对话框，并调用现有 restore API。恢复会创建新的当前代际，保留所有历史记录；成功后自动选择新代际并刷新工作台。旧版本不能被误当成最新版本继续执行全局重生成。

### 4.2 完整规划复核

规划复核先展示 Brief、Outline 和 DesignSystem 摘要，再展示逐页 PageSpec。契约以明确的 TypeScript 类型替代宽泛的 `Record<string, unknown>`；遇到向前兼容字段时仅在边界解析层保留未知值。

审批、整套修订和定向页修订的现有服务端语义保持不变。加载失败必须显示错误，不得呈现空白规划并允许批准。

### 4.3 页面质量

页面卡片显示质量结论：通过、警告、失败或尚未完成。页面检查器提供独立“质量”页签，展示布局、文字/OCR 和其他安全质量项；未知的报告字段以安全摘要呈现，不直接 dump 任意 JSON。

质量失败给出可执行方向：修改页面、重新生成，或在导出阶段明确接受风险。前端不把警告自动升级为失败，也不自行覆盖服务端结论。

### 4.4 页面编辑与澄清

页面编辑明确区分：

- 文字/样式修改：`resample_visual=false`，不会调用图片模型；
- 视觉修改：`resample_visual=true`，可能调用视觉与图片模型并产生费用。

视觉修改必须使用付费确认对话框。首版继续采用自然语言定位，不增加手工框选；服务端若返回需要澄清的 PageEdit 状态，界面显示问题并通过 `/page-edits/{edit_id}/resume` 提交补充指令或服务端认可的目标框。

为保证刷新后仍能继续澄清，后端工作台或页面详情需要投影当前待处理 PageEdit 的安全状态、问题和允许提交的字段。不得只依赖创建请求的瞬时响应。

### 4.5 强制导出

普通导出始终先发送 `forced=false`。收到 `export_not_ready` 时，界面展示当前页面质量风险并开放“确认风险继续导出”。用户必须在共享 Dialog 中勾选确认，随后发送 `forced=true` 和非空 `risk_acknowledgement`。

强制导出沿用相同格式、JPG 质量或 PDF DPI。取消确认不创建任务；确认失败保留对话框和错误信息，允许安全重试。

### 4.6 项目与素材删除

项目列表和素材面板增加危险操作入口。两者都使用共享确认 Dialog，不使用原生 `window.confirm`。

- 项目删除成功后从缓存移除并留在项目列表；若从项目工作台触发则返回项目列表。
- 素材删除成功后刷新列表，并从当前选择集中移除该素材。
- 忙碌、失败和并发冲突状态必须可见，不执行乐观删除。

## 5. P2：视觉和交互一致性

### 5.1 设计令牌与组件样式

视觉系统使用正式设计方向中的克制蓝紫强调色，并保留暗色工作台。补充语义颜色、间距、字号、边框、焦点环和过渡 token。报告涉及的 feature 组件把内联布局魔法数迁入命名明确的 CSS 类；动态数值样式仅保留进度百分比等真正运行时数据。

共享样式覆盖按钮、危险按钮、工具栏、卡片、状态徽章、数据摘要、版本选择器、进度条、骨架和对话框。样式调整不能降低对比度、键盘焦点可见性或 `prefers-reduced-motion` 兼容性。

### 5.2 状态、图标与产品语言

建立唯一状态元数据映射，为每个 Run/Page/Export 状态提供中文标签、语义色、轻量内联 SVG 图标和必要动作说明。图标组件带 `aria-hidden`，可理解文本始终存在；不使用 emoji 作为唯一语义通道。

诊断轨迹可以同时显示安全的内部状态值，但普通工作台优先显示“正在生成”“等待确认”“等待自动重试”“需要人工恢复”等产品语言。

### 5.3 对话框、进度与首次引导

所有付费、恢复、删除和强制导出确认复用现有可访问 Dialog。单页重生成移除 `window.confirm`。

生产进度只使用服务端当前步骤和页面统计，显示阶段进度条与逐页缩略图骨架，不计算 ETA。未知总数使用不定进度表现。

空项目首页同时提供创建项目和配置模型路径；云模式未配置时提前说明哪些动作会被阻断。确定性模式不显示不必要的 Ark 设置阻断。

## 6. 错误与数据一致性

已知 API 冲突转换成中文、可执行的下一步。未知异常继续使用共享 `ErrorBanner` 和固定中文回退，不展示任意服务端堆栈、请求体、凭据或未清洗响应。

Mutation 成功后只失效其影响的 Query：项目工作台、Run snapshot/trace、成本、Deck 历史、页面或素材列表。Mutation 失败不得提前清空用户输入、关闭对话框或切换当前版本。

所有危险或付费 Mutation 继续依赖服务端 expected generation、expected attempt 或幂等键保护；按钮禁用只改善体验，不能替代服务端校验。

## 7. 测试与验收

所有行为修改遵循测试先行：先加入能复现缺口的失败测试，确认失败原因，再实施最小代码并运行相关测试。

前端组件测试至少覆盖：

- Operation 逐条授权及 Run 级恢复门控；
- 多币种成本、无预算和未知费用显示；
- 全部状态中文语义和 due time；
- Deck 版本切换及恢复；
- Brief、Outline、DesignSystem 与强类型 PageSpec；
- 页面质量摘要与详情；
- 文字/样式和视觉编辑分流及澄清恢复；
- 强制导出的风险确认请求；
- 项目与素材删除确认；
- 自定义对话框替代原生 confirm；
- 首次引导、进度条和关键可访问性行为。

后端契约测试覆盖新增成本聚合、重试时间和待澄清 PageEdit 投影的授权、项目隔离与空值语义。Playwright 核心流程覆盖首次设置引导、未知结果恢复、版本恢复、视觉编辑、质量风险导出和删除操作，不触发真实 Provider。

完成前运行：前端全量 Vitest、TypeScript typecheck、Vite build、相关 Python 测试、Python 全量测试、`compileall` 和 `git diff --check`。由于当前工作区包含既有未提交改动，验收报告区分本批次改动与既有状态，不覆盖或回退用户内容。

## 8. 完成标准

- 用户可以在 UI 中完成未知远端结果的 Operation 授权和后续 Run 恢复，不再遇到无下一步的 409。
- 工作台显示真实账本成本、预留、未知费用和可用预算。
- 报告列出的 Deck 代际、完整规划、质量、视觉编辑、强制导出、项目/素材删除能力全部可达。
- 付费和危险操作使用统一、可访问的确认交互。
- 普通界面状态使用一致的中文、图标、颜色和动作说明。
- 报告涉及组件不再依赖散落的静态内联样式；进度、骨架和首次引导形成一致体验。
- 新增行为有自动化回归测试，既有前端、后端和确定性 E2E 不回退。
