# 本地安全与存储能力协议

## 威胁模型

首版需要防御：

- 恶意网页访问 localhost API。
- DNS rebinding、伪造 Host/Origin 和跨站请求。
- 路径穿越、符号链接逃逸和 Zip Slip。
- 恶意或异常大的 PDF、图片和压缩数据。
- 素材中的提示注入诱导 Agent 调用不应使用的工具。
- 日志、Trace、诊断包和错误消息泄露 API Key 或用户内容。
- 不可靠文件系统破坏 SQLite WAL、文件锁或原子重命名假设。

本地访问令牌不能防御已经获得同一操作系统用户权限的恶意进程。此类威胁需要依赖操作系统账户隔离、Keyring 和文件权限。

## 本地 API 访问

- 首次启动生成高熵本地访问令牌，保存在系统 Keyring；Docker 模式从 Secret 或受限文件加载。
- Web UI 首次打开通过启动 URL 或一次性交换流程获得短期会话，不把长期令牌写入 URL 历史。
- 所有修改状态、读取项目内容和 SSE 连接的 API 均需认证。
- 校验 `Host` 仅为已批准的 localhost 地址和端口，防御 DNS rebinding。
- 校验 `Origin`；拒绝缺失或不在允许列表的浏览器跨域写请求。
- 如果使用 Cookie，会话 Cookie 必须为 HttpOnly、SameSite，并为写请求增加 CSRF Token。
- CORS 不是认证机制，不能代替访问令牌。

## 文件与路径安全

- 所有用户路径先解析为 canonical absolute path，再验证位于 Workspace 根目录下。
- 打开文件前和写入后均验证目标没有通过符号链接、junction 或挂载点逃出 Workspace。
- 服务端使用 Artifact ID 映射文件，不接受前端传入任意绝对路径。
- ZIP 中的文件名必须标准化并拒绝绝对路径、`..`、驱动器前缀和符号链接条目。
- 导出 ZIP 由服务端生成固定安全名称，不能直接复用用户上传路径。
- staging 与最终文件必须处于同一文件系统，确保原子重命名语义成立。

## 输入限制

按 Provider 和本地解析器分别配置硬限制：

- 单文件及项目累计上传大小。
- PDF 页数、对象数量和解析时间。
- 图片宽高、总像素、帧数和解压后内存。
- Markdown 长度、嵌套深度和外部资源数量。
- 压缩比和嵌套压缩文件。
- OCR 和预览生成超时。

解析前先执行廉价的文件头和元数据检查。首版优先将 PDF/图片解析放入受限制的子进程，设置超时、内存和 CPU 限额；平台无法提供强资源隔离时至少保证超时、进程终止和独立临时目录。

## 不可信素材与提示注入

- 用户素材中的文字始终标记为 `untrusted_source_content`。
- 素材不得改变系统提示、工具白名单、预算、Provider 配置或文件权限。
- Agent 只从结构化控制面接收工具能力，不从 PDF/Markdown 中解析可执行工具指令。
- 引用素材时保留来源边界，Prompt 明确要求将其作为数据而不是指令。
- 任何外部发送、文件删除或扩大权限的操作都不能由素材内容触发。

## Provider 数据披露

设置页按能力展示：

- 哪些字段发送给 DeepSeek、Qwen、豆包和 Seedream。
- 是否发送原始文件、裁切图片、OCR 文本、Prompt、页面缩略图或诊断信息。
- Provider 地域、配置的数据保留说明和对应文档链接。
- 关闭某类发送后的功能降级结果。

每次调用 Trace 记录字段类别和 Artifact ID，但默认不复制完整敏感内容。

## 数据目录能力探测

数据目录不是任意可写目录。首次选择和每次启动执行能力探测：

1. 解析真实路径并检查权限。
2. 检测已知网络盘、远程挂载和常见同步目录。
3. 验证同目录原子重命名。
4. 验证排他文件锁。
5. 验证临时文件、`fsync` 和可用空间。
6. 尝试启用 WAL，并验证实际返回的 journal mode。

SQLite 官方说明 WAL 要求所有进程位于同一主机，不能依赖网络文件系统共享内存语义：[SQLite WAL](https://www.sqlite.org/wal.html)。

默认行为：

- 已知网络文件系统：拒绝作为状态数据库目录。
- 不支持 WAL 但具备可靠锁和原子重命名：允许回退到 rollback journal，并降低并发写入频率。
- 同步盘：默认警告并建议更换；无法验证能力时拒绝启动生产模式。
- 用户可以将导出目录设在其他位置，但数据库和活跃 Workspace 必须满足能力要求。

## SQLite 配置

首版明确配置并记录：

- `journal_mode`：本地可靠文件系统使用 WAL，否则按探测结果回退。
- `synchronous`：生产默认 `FULL` 或经故障测试确认的策略。
- `busy_timeout`：配置化并记录实际值。
- `wal_autocheckpoint`：配置化，结合事件写入量测试。
- `foreign_keys=ON`。

状态更新、预算预留、Provider Operation/Attempt 和 Artifact 元数据使用短事务写协调器。高频 Trace/Metric 先进入有界内存缓冲，再批量写入独立观测表，不能长期占用 SQLite 单写者锁。

## 备份与恢复

- 使用 SQLite Online Backup API 或经过验证的数据库备份流程，不在活跃 WAL 状态下只复制主 `.db` 文件。
- 备份记录 Schema 版本、应用版本和 Artifact 清单摘要。
- Artifact 大文件采用增量备份或内容寻址复用。
- 恢复后先运行数据库迁移、完整性检查和 Artifact 对账，再启动 TaskSupervisor。
- 保留最近若干个成功备份，删除遵循可恢复策略。

## 测试

- 恶意网页无法无令牌访问 localhost API 或 SSE。
- 非法 Host、Origin 和 CSRF 请求被拒绝。
- `../`、绝对路径、符号链接和 Zip Slip 无法逃出 Workspace。
- 超大像素图片、压缩炸弹和超时 PDF 被终止。
- 素材提示注入不能扩大工具或文件权限。
- WAL 不可用时行为符合探测与回退规则。
- 活跃数据库备份和恢复后通过完整性与 Artifact 对账。
