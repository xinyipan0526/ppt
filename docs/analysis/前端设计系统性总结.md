# 前端设计系统性总结

> 审查方式：只读代码审查（未修改、新增或删除任何源码）。
> 结论均附源码文件证据；行号以审查时工作区为准，后续变动可能导致偏移。
> 路径均相对于仓库根目录（`E:\chatgpt_project\ppt`）。
> 审阅范围：`web/` 前端全部源文件 + 后端 `src/ppt_agent/api/` 暴露的 UI 投影能力，用于判定“后端已具备、前端没接上”的断层。

---

## 0. 一句话结论

前端是一个**“后端能力强、前端只接了一半”的窄工作台**：核心链路（项目→资料→澄清→规划复核→生产→画廊→单页编辑→导出）已经闭环且计费护栏、断线恢复、密钥安全这些难点做得很稳；但**关于“恢复/重试/成本/版本”的一整类能力后端早已实现，前端却只露出工具按钮级别的一小部分**。最典型的正是用户指出的“重试”：真正的远端结果未知重试在 UI 里是一条**走不通的死路**（见 §3.1）。此外还存在使用路径不清晰、信息呈报不完整、视觉系统半成品等三类问题。

| 维度 | 强项 | 短板 |
|---|---|---|
| 核心链路完整性 | 全流程闭环、可恢复 | 多处“后端有接口、前端没按钮” |
| 重试/恢复 | 计费护栏正确 | 远端未知结果的重试 UI 不可用 |
| 信息呈报 | 页面进度、运行轨迹、安全错误 | 无成本、无预算、无质检结果、无旧版本切换 |
| 使用清晰度 | 类型化澄清、焦点圈定 Dialog | 首次使用无引导、导出强行走不通、原生 confirm 不一致 |
| 美观/一致性 | 暗色 token 基础好 | 内联样式泛滥、状态徽章无颜色区分、无进度条/图标 |

## 1. 前端现状全景

### 1.1 技术栈与架构

- React 19 + TypeScript + Vite + React Router 7 + TanStack Query 5 + React Hook Form + Zod + Vitest + Playwright（`web/package.json`）。
- 服务器状态全部归属 TanStack Query；`main.tsx` 建唯一 `QueryClient`（`staleTime: 2s`、`retry: 1`、`refetchOnWindowFocus: false`）。
- 布局为**左侧窄轨 + 主舞台**两段式（`web/src/app/App.tsx`），路由只有三条：`/`（项目列表）、`/settings`（模型设置）、`/projects/:projectId`（工作台）。
- 数据流：`ApiClient` 统一处理 HttpOnly Cookie 会话、CSRF、401 重引导、错误归一化（`web/src/api/client.ts`）；`RunEventStream` 走 SSE + `cursor_expired/run_unavailable` 后 3s 有界轮询兜底（`web/src/api/events.ts`）。

### 1.2 目录与职责

| 目录 | 职责 |
|---|---|
| `app/` | 壳与路由（`App.tsx`、`main.tsx`） |
| `api/` | 契约类型 `contracts.ts`、`client.ts`、`events.ts` |
| `components/` | 共享 `Dialog.tsx`（焦点圈定/Escape/aria）、`ErrorBanner.tsx` |
| `features/projects/` | 项目列表、工作台装配 |
| `features/materials/` | 上传、资料列表、解析重试 |
| `features/planning/` | 创作意图、澄清表单、规划复核 |
| `features/deck/` | 画廊、幻灯片、页检查器、页历史、全局重生成 |
| `features/runs/` | 运行状态、恢复动作、运行轨迹、安全错误格式化 |
| `features/exports/` | 异步导出面板 |
| `features/settings/` | Provider/模型配置 |
| `styles/` | `tokens.css`（7 个颜色 token + 圆角/阴影/字族）、`global.css`（全部类样式） |

### 1.3 已实现能力（对照设计规格）

- ✅ 项目创建/列表（含最近任务、成品版本数、资料数徽章）。
- ✅ 资料上传（拖拽 + 文件选择）、解析状态徽章、**解析失败重试**。
- ✅ 创作意图输入 + 资料多选 → 规划 Run。
- ✅ 类型化澄清表单（text/number/single_select/multi_select + reason + required）。
- ✅ 规划复核：逐页批准 / 定向页修订 / 整套反馈 / 取消。
- ✅ 生产启动、单页重新生成、文字/样式局部修改（`resample_visual:false`）、页多版本历史与恢复。
- ✅ 全局重新生成（带费用确认勾选、幂等 expected_generation）。
- ✅ 运行状态：取消（含终态幂等、取消收尾）、页级完成/失败进度、失败/取消/恢复提示。
- ✅ 运行轨迹（Steps/Events/Operations/Attempts 只读展示 + 安全错误码格式化）。
- ✅ 异步导出（`sessionStorage` 回放 + 轮询到 available 才给下载），支持 JPG 质量 / PDF DPI。
- ✅ 模型设置（zod 校验、推荐模型预选、待激活态、删除凭据）。
- ✅ 安全边界：API Key 不进前端存储；`ErrorBanner` 统一 role=alert；`Dialog` 焦点圈定/Escape/焦点还原。
- ✅ 付费动作门控：`setup_required` 时禁用所有会触发云 Provider 的动作。

## 2. 架构与工程质量评价

**优点**

- 服务器状态与 URL 状态边界清晰，没有全局状态库，符合规格。
- `ApiClient`/`RunEventStream` 把会话、CSRF、错误、断线恢复收敛到两处，feature 组件干净。
- 关键交互都有单元测试（Dialog 焦点、RunStatus 取消幂等、ExportPanel 竞态、RecoveryActions 门控、GlobalRegenerate 费用确认等）。

**债务**

- 🟡 **样式系统半成品**：只有两个全局 CSS 文件，feature 内部大量 `style={{...}}` 内联（`marginTop: 14/16/18`、`fontSize: 12/13` 等魔法数散落各文件），token 未被系统化消费，后续改主题/间距成本高。
- 🟡 **状态徽章无类型化颜色映射**：`global.css` 只给 `succeeded/ready`、`failed/recovery_required`、`running/queued` 三类配色；`waiting_for_user`、`waiting_for_retry`、`cancel_requested`、`cancelled` 等状态落到默认淡色，视觉上无法一眼区分“等输入/等重试/已取消”。
- 🟡 **`PageSpecCard`/`PlanReview` 用 `Record<string, unknown>`** 承载页面规格，丢失了类型安全（对比 `contracts.ts` 其余部分都是精确类型）。
- 🟢 少量未使用的显式 `ApiError` 手工拼接文案（`PlanningInput.tsx:9`）与 `ErrorBanner` 并存，属一致性残留。

## 3. 缺失的功能（后端已具备、前端没接上）

### 3.1 🔴 远端“结果未知”的重试在 UI 里走不通（用户所指的“缺重试”）

这是当前最严重的前端缺口：

- 后端把重试分成两层：
  - **Run 级** `/runs/{run_id}/authorize-local-retry`（`src/ppt_agent/api/operations.py:98`）；
  - **Operation 级** `/operations/{operation_id}/authorize-retry`（`operations.py:65`，需 `operation_id + expected_attempt_id`）。
- 关键逻辑：`authorize-local-retry` 会先统计 `outcome_unknown/reconciling/cancel_requested` 的 Attempt，**只要存在就返回 409**“run has uncertain Provider attempts; authorize those operations first”（`operations.py:106-126`）。也就是说，真正因为“远端结果未知”进入 `recovery_required` 的任务，**必须先按 Operation 逐条授权**。
- 前端只接了 Run 级：`RecoveryActions.tsx` 仅调用 `authorize-local-retry`。于是典型场景变成：用户点“授权恢复”→ 后端 409 → `ErrorBanner` 显示一句英文 detail → **没有任何下一步入口**。
- 前端其实已经把 Operation/Attempt 渲染出来了（`RunTrace.tsx` 的 Operations 段列出了 `operation.id`、`attempt.id`、`attempt.status`、`error_code`），但**只读、无授权按钮**。数据在、动作不在。
- 结论：**最需要人工重试的场景，前端无法完成恢复**。这应是“补重试功能”的第一优先级。

### 3.2 🔴 无成本/预算展示

- 后端 `GET /projects/{project_id}/costs` 已存在（`operations.py:85`），组件内设计规格也要求顶栏“budget/cost”和对单页编辑“显示可用预算”。
- 前端全局无任何 cost/budget 相关查询或展示（grep `budget|cost|费用|余额` 只命中提示文案，无数据绑定）。
- 后果：这款产品把“成本可控”当核心卖点，但用户从头到尾看不到花多少钱、账户还剩多少、本次操作预计预留多少。成本护栏变成黑盒。

### 3.3 🔴 无成品版本（Deck generation）切换 / 对比 / 恢复

- 后端有 `GET /projects/{project_id}/deck-generations`（`workspace.py:133`）与 `POST .../deck-generations/{id}/restore`（`workspace.py:140`），且工作台数据里也返回了 `deck_generations` 数组。
- 前端只取 `latestDeck`（按 generation 降序取第一，`ProjectWorkspace.tsx:47-48`），画廊永远显示最新一版；全局重新生成后，旧版本**从主视图完全不可见**（只有页级 `PageHistory` 能回看单页版本）。
- 规格明确要求“上一代仍可选择”“整套代际可比较/恢复”，均未实现。

### 3.4 🟠 局部视觉编辑（Qwen 定位 + Seedream）未暴露

- 后端 `POST /pages/{page_id}/edits` 支持 `resample_visual: bool` 与 `target_box`（`production.py:44-49,177`），并有 `/page-edits/{edit_id}/resume` 处理编辑澄清（`production.py:199`）。
- 前端 `PageInspector` 的“执行修改”永远 `resample_visual: false`（`PageInspector.tsx:12`），没有“视觉修改”入口，没有 target_box，也没有接线编辑澄清恢复。
- 结果是“自然语言定位 + 图片局部编辑”这一期能力在 UI 里不可达，用户只能“整页重新生成”或“改文字”。

### 3.5 🟠 导出“强制导出 + 风险确认”不可达

- 后端 `ExportCreate` 有 `forced: bool` 与 `risk_acknowledgement`（`production.py:58-64`）；当页面质检未通过时导出会回 409 `export_not_ready`。
- 前端 `ExportPanel.begin` 固定 `forced: false` 且从不发送 `risk_acknowledgement`（`ExportPanel.tsx:139-151`）。失败时只给一句泛化 fallback“请先修复或明确确认风险”，**没有“确认风险继续导出”按钮**。
- 规格要求“forced-export acknowledgement when required”，未实现。

### 3.6 🟠 规划复核看不到 Brief / Outline / DesignSystem

- 后端 `plan-detail` 返回 `brief`、`outline`、`design_system`、`pages`（`planning.py:230-243`）。
- 前端 `PlanReview` 只渲染 `pages`（`PageSpecCard` 列表），**Brief、提纲、设计系统整块未展示**（`PlanReview.tsx:14`）。
- 用户在批准整套规划前，看不到 Agent 对受众/场景/设计方向的判断，只能看到每页的一行标题和一句 objective。

### 3.7 🟠 页质量（quality）结果不展示

- 契约 `PageGeneration.quality` 存在，后端也在页面历史上传了 `quality_artifact` 内容（`workspace.py:347-349`）。
- 前端既不在卡片上显示质检徽章，也不在 `PageInspector` 任何 Tab 里展示 quality 结果。规格要求“每张卡片显示质量结果”，未实现。

### 3.8 🟠 其他未接线的后端能力

- `waiting_for_retry` 的**重试时间（due time）**：状态类型存在（`contracts.ts:1`），后端有 retry-safe 调度，但前端没有展示“将于 X 自动重试”或“最多重试 N 次”的任何信息。规格要求展示 due time。
- **项目删除**（`DELETE /projects/{id}`，`projects.py:59`）与**资料删除**（`DELETE .../materials/{id}`，`materials.py:120`）均无 UI 入口。
- **Provider 活体测试** `/providers/{provider}/test`（`providers.py:42`）未接线（前端用的是 adapter 级 `test`，功能上够用，属低优先级）。

### 3.9 已具备但体验稀薄的重试能力（澄清）

为避免误读，明确列出**已经存在**的重试入口：

| 场景 | 现状 |
|---|---|
| 资料解析失败 | ✅ 有“重试”按钮（`MaterialPanel.tsx:13`） |
| Run 取消 / 取消收尾 | ✅ 幂等取消 + “继续完成取消”（`RunStatus.tsx`） |
| Run 级本地重试授权 | ✅ `RecoveryActions`（但见 §3.1 被远端未知结果挡住） |
| 单页重生成 / 页版本恢复 | ✅ `PageInspector` / `PageHistory` |
| 全局重生成 | ✅ `GlobalRegenerateDialog`（带确认） |
| 导出失败重跑 | 🟡 靠再次点同一格式按钮复用同一 export id；无明确的“重试”文案（`ExportPanel.tsx` 隐式） |
| 规划/生产 Run **硬失败**后重试 | ❌ 无“重试此 Run”入口，只能手动重新发起全新 Run |

## 4. 使用清晰度问题

1. **首次使用无引导（onboarding）**：新用户打开即见空项目列表，没有“先配置模型”的引导；`setup_required` 阻断卡只在进入某个项目后才出现，且入口为 `/settings` 链接，路径绕。
2. **恢复/重试的死路**（§3.1）：点“授权恢复”被 409，且提示是后端英文原文，用户无法自行走完。
3. **导出质量问题无解**（§3.5）：失败只提示“请先修复或明确确认风险”，但界面上既没有“修复”入口也没有“确认风险”入口。
4. **错误呈现一致性残留**：多数 mutation 已收敛到 `ErrorBanner(ApiError.message)`，但 409 authorized-retry 的英文 detail 原样展示、`PlanningInput` 仍手工拼文案；运行失败通知与轨迹中错误分两处展示，缺一个统一的“错误 → 下一步动作”指引。
5. **审批信息不足**（§3.6、§3.7）：批准规划/查看成品时，看不到 Brief/提纲/设计方向/质检结果，用户“确认”的是不完整信息。
6. **状态语义不直观**：`waiting_for_retry`、`waiting_for_user`、`recovery_required`、`cancel_requested`、`cancelled` 等状态只显示英文徽章，无中文解释、无“该做什么”的引导（`RunStatus.tsx` 里所有状态贝徽章都是`class={badge status}`）。
7. **无 ETA**：长任务只有“当前步骤 + 页数”，无剩余时间估计（规格中明确“不计算 ETA”是后端计划里的决定，但当前连阶段级进度条都没有）。

## 5. 美观/一致性问题

1. **内联样式泛滥**：`DeckGallery`、`RunStatus`、`PageInspector`、`ExportPanel`、`MaterialPanel` 等大量 `style={{...}}`，间距（12/14/16/18/22）、字号（11/12/13）不一致，视觉节奏靠手撸，不具备可调的主题一致性。
2. **状态徽章配色缺失**（§2）：多数运行状态落到同一种灰，重要状态（等输入/等重试/恢复要求/已取消）无法用颜色区分。
3. **原生 `window.confirm` 与自定义 Dialog 混用**：单页重生成用系统原生弹窗（`PageInspector.tsx:14`），而全局重生成用自定义 `Dialog` + 勾选确认——同一类“会产生费用”的操作体验不一致，且原生弹窗无暗色主题、无焦点管理，破坏整体视觉。
4. **无图标体系**：全站用文本/emoji（`＋`、`↻`）充当按钮图标，规格里的“图标 + 文字双通道表达状态”未落实。
5. **无进度条**：页进度仅为文字“页面进度：x/y 已完成”；生产阶段无逐页缩略图占位/骨架（画廊在未返回时只有整卡 skeleton）。
6. **规范落差**：设计规格写“克制的蓝紫强调色”，实现用的是霓虹黄绿 `#e8ff58`（`tokens.css:5`）——非错误，但与规格不一致。
7. **响应式只覆盖 900px 一档**：窄于 900px 时只把侧轨压成 72px 图标 + 工作台单列，未做平板/移动的完整降级（规格定位桌面端，可接受，但仓库当前无 Safari/Firefox/移动端认证）。

## 6. 优先级改进路线（建议）

### P0 —— 先补“走不通”的重试与资金可视化（直接回答“缺重试”）

1. 在 `RunTrace` 的 Operations 段给“结果未知/待恢复”的 Attempt 加**逐条授权按钮**，调用 `/operations/{id}/authorize-retry`（传 `expected_attempt_id`），授权后再回到 Run 级 `authorize-local-retry`；若只做其一至少要打通 Operation 级。
2. 接 `GET /projects/{project_id}/costs`，在项目/工作台顶栏加**成本与账户余额展示**（至少有累计已结算金额 / 本任务预留）。
3. 在 `recovery_required` / `waiting_for_retry` 状态给出一句**中文“下一步该做什么”**（去 Provider 控制台核对 → 逐条授权 → 本地重试）+ 展示重试 due time（若有）。

### P1 —— 补“后端有、前端缺”的产品能力

4. 成品版本切换器 + 整套代际恢复（接 §3.3 两接口）。
5. 规划复核页展示 Brief / Outline / DesignSystem（§3.6）。
6. 页卡片与检查器展示 quality 结果（§3.7）。
7. 导出“确认风险继续导出”→ 传 `forced` + `risk_acknowledgement`（§3.5）。
8. 暴露局部视觉编辑入口与编辑澄清恢复（§3.4，二期能力可先明确收起）。
9. 项目删除 / 资料删除入口（含确认对话框）。

### P2 —— 视觉与一致性收敛

10. 建组件级样式（或用 CSS 变量 + 工具类）替换内联魔法数；补齐状态徽章全色映射与“文字+图标”状态表达。
11. 用自定义 `Dialog` 替换 `window.confirm`，统一“产生费用”类操作的一致确认体验。
12. 补数据骨架/进度条、首用 onboarding、状态语义中文解释。
